# 7. Components and functions

[← Index](TECHNICAL_DOCUMENTATION.md)

All game code is in `game/src/` (about 3,400 lines). Namespaces: `CaucasianEagle` for the game module and constants; `Doorways` for the kit and HUD, which were moved out of the engine and keep its namespace for now ([10-tech-debt-risks.md](10-tech-debt-risks.md), D3).

## 7.2 `CaucasianEagle::Game`

| Function | When the engine calls it | What it does |
|---|---|---|
| `Configure` | At registration, before the engine starts | Sets scene id, window title, user-data folder |
| `Prepare` | Once, after engine initialisation, normal launches only | Loads the `EagleV1` bundle with its 31 clips; sets movement, camera and input options; starts `NyxaraKit`; starts the showcase if requested |
| `ScaleFrameTime` | Every frame, before simulation | Kit hit-stop factor times the journey's time scale (1 except in the test pilot) |
| `Update` | Every frame while gameplay runs | Kit, then journey |
| `Draw` | Every frame, after the world is drawn | Mountain, journey, then kit |
| `AdjustEnvironment` | Every frame | Mountain's moonlight, then the journey's per-region fog and light |
| `DrawHud` | Every frame, in the HUD pass | Draws the game HUD when a kit snapshot is valid and the engine's melee session is active; otherwise lets the engine draw its own |

## 7.3 `NyxaraKit`

One object, reached through `Doorways::GetNyxaraKit()`.

### Actions

An action is one row of the `Acts` table: display name, animation clip, playback rate, end time, and up to four hit times (in clip seconds). The enum `NyxaraKit::Act` indexes it.

| Act | Input | Name shown | Clip |
|---|---|---|---|
| `Slash1` | LMB (first, then every other click) | LEFT TALON | `BasicAttack` (mirrored to the left hand) |
| `Slash2` | LMB (second, then every other click) | RIGHT TALON | `SlashLeft` |
| `Heavy` | RMB | CHARGED SLASH | `HeavyAttack` |
| `Skill1` | F | TALON DASH | `Skill1` |
| `Skill2` | V | FEATHER CYCLONE | `Skill2` |
| `Skill3` | C | MOON LEAP | `Skill3` |
| `Combo1L` / `Combo1R` | after F: LMB / RMB | TWIN TALONS / RISING EAGLE | `Combo1L` / `Combo1R` |
| `Combo2L` / `Combo2R` | after V: LMB / RMB | TEMPEST TRIPLE / WHIRLWIND TALONS | `Combo2L` / `Combo2R` |
| `Combo3L` / `Combo3R` | after C: LMB / RMB | SOUL WEAVE / MOONFALL DIVE | `Combo3L` / `Combo3R` |
| `Guard` | E (hold) | SWORD BARRIER | `Guard` |
| `Swap` | Q | SWORD EXCHANGE | `SwordSwap` |

### Main functions

| Function | Purpose |
|---|---|
| `Initialize` | Builds effect meshes in code, loads six effect textures from `assets/Compiled/Effects/Nyxara`, places the shades, sets `GameSession().Active` |
| `ReadKeys` | Reads the mouse buttons and Q, E, F, V, C, Shift; in showcase mode returns scripted keys instead |
| `ScaleFrameTime` | Returns 6% of real time while a hit-stop is running |

| `Impact` | Hit feedback: hit-stop, camera shake, sparks, cross-slash, ring |

## 7.4 `NyxaraHud`

`NyxaraHudState` is a plain snapshot: skill cooldowns, combo availability and names, current action flags, the move name and its timer, and up to eight projected enemy bars. `DrawNyxaraHud(ui, context)` reads it plus the engine's vitals text (`"HP %d EN %d"`) and draws the emblem, health and energy bars, the eight skill slots, the combo prompt, the move name and the enemy bars through `Ui`. It holds no gameplay state; it keeps a few values for animation only (health trail, hit flash, the flash of a skill that is ready again).

### `Ui` (GameUi)

`Game::DrawHud` makes one `Ui` per frame and passes it to `DrawNyxaraHud`, `Journey::DrawHud` and `Story::DrawJournal`. Sizes are given in layout units (1 unit = 1 px at 1280 × 720) and multiplied by `Ui::S`, the engine's UI scale. Artwork comes from one atlas loaded by `Ui::LoadArt` in `Game::Prepare`; start-up fails with a message if the atlas is missing. A sprite with a margin (soft shadow) is drawn so that the rectangle the caller gives is the solid shape.

### Story journal (Story)

`Story::Journal` is the state (page, fade, scroll, what is unlocked, unread flags); `Journey` owns it and `Story::DrawJournal` draws it. `Journey::UpdateJournal` reads F1, M, A / D, W / S, the arrows and PageUp / PageDown with the engine's `IsDoorwaysKeyDown` (the key, or the controller button bound to it). The same function opens the world map on M; the journal and the map are never open together and share everything below. While the journal is open `Journey::TimeScale` returns `JournalTimeScale`, the kit ignores input (`NyxaraKit::SetInputBlocked`) and the engine's move, jump, dodge and inventory actions are added to `GameSession().SuppressedActions`. The journal closes by itself when the engine reports that gameplay input is not allowed (a menu, or the window lost focus).

**Her menu and the guide.** The game sets `GameSession().OwnPauseMenu`, so the engine's pause menu never shows: on Escape (or Start on a controller) in play the engine only sets `EscapePressed`. `UpdateJournal` reads and clears it: Escape closes any open window, and with none open it opens her menu (`mPauseOpen`, drawn by `Journey::DrawPause`, `PauseRows` rows chosen with W / S and taken with Enter or Space). Rows that need the engine set `GameSession().MenuRequest` (`Settings`, `MainMenu`, `Exit`); the game saves first for the last two. The guide (`Guide.cpp`: `Guide::Draw(ui, page, fade)`, `Guide::PageCount` pages of fixed text; `mGuideOpen`, `mGuidePage`) opens from her menu or from the start screen's Guide button (`GuideRequested`, then `mGuideFromStart`: closing it asks for `MainMenu`). Her menu and the guide count as open windows for everything in this section: time scale, blocked kit input, suppressed engine actions. The guide's text repeats `docs/manual.md` and must be changed with it.

**The whole land.** Outside a fight `Journey::Leash` does not hold her to the road: the limit `road width - 0.5` applies only while `mFighting`. The ground she stands on is the engine's: the world scene has `COL_Walkable_Land_####` pieces (the whole terrain in pieces of 16 cells, without water, the chasm round the sanctuary and the foot of the mountain; `build_land_collision` in `art/world/build_world.py`), and where a face is too steep or there is no piece the engine holds her, which is what keeps her on the causeway and the last climb. She is pushed out of circles: the `O x z radius` lines of `Road.txt` (boulders, props, gate piers) and of `Cities.txt` (each house as a row of circles along its longer side, never reaching onto the street), all in 16 m squares in `mObstacleGrid` through `AddObstacle`, and tree trunks (`Nature::PushFromTrees`). The wall of the next unwon arena stops her only on the road: within `WallReach` of the road's edge and within 6 m beyond the wall; farther out she passes, `mPastWall` is set, and the wall does not pull her back. `UpdateEncounter` starts a fight only when she is on the clearing (`mLateral` within the road's width), a city counts as entered within `CityReach` of the road's edge, and the finale begins only on the road. Arenas are won in order, so walking round one wins nothing. Creatures keep to the road and their ground is the road's height.
**Her settings window (`Settings.cpp`).** `Game::Prepare` sets `GameSession().OwnSettings`, so the engine's settings screens never open. `Settings::Draw` is called every frame from `StartScreen::Draw` (pointer free, reads Esc itself) and from `Journey::DrawHud` over her menu (the journey passes the engine's `EscapePressed` on through `Settings::Back`). It reads `GameSession().Settings.Active` and asks for changes with `Settings.Ask(wanted)`; the engine applies the categories that differ and saves. Window mode and size are held as a candidate until "Apply the window"; the engine then puts the change on trial (`Settings.Confirming`, `SecondsRemaining`) and the window shows "Keep this window?" and answers with `DisplayAnswer`. Fifteen rows in four sections; sliders repeat while A or D is held. Testing: `CAUCASIAN_EAGLE_SETTINGS=1` holds it open, `CAUCASIAN_EAGLE_SETTINGS_KEYS` plays keys into it (W S A D, E = Enter, X = Esc); every change of the applied state is logged as `CaucasianEagle settings: ...`.

**The pointer.** `GameSession().Cursor` names `assets/ui/Cursor/Pointer.cur`; the engine makes it the window's pointer. While any of her windows is open `UpdateJournal` sets `GameSession().FreeCursor`, so the engine shows the pointer and stops turning the camera with the mouse. Windows register what can be pressed while they draw (`Pointer::Add` in `GameUi`: her menu rows, the cards of the growth window, the rune cards, the page key); `UpdateJournal` reads them on the next frame: moving the pointer over a zone chooses it, a click is Enter on it. The pointer chooses only when it moves, so W and S still work with the pointer resting on a row. After a window closes her kit stays blocked until the left button is up, so the closing click is not a sword blow.

**Where she begins.** `Journey::StartPoint()` is the road sample at `StartS` (2 m). `Game::Prepare` gives it to the engine as the spawn point (`OwnSpawn`); the first update of a new journey, `Restart`, and a respawn before the first arena is won put her there with `Teleport`.


**The way.** `Journey::UpdateWay` (after `Leash`) decides whether the way is shown: she is more than `WayOffRoad` beyond the road's edge, or her nearest road sample is past the next unwon arena (`mWayBack`). The target is the road sample `WayStep` metres from her nearest one toward that arena (or the end of the road). `Draw` runs ten gold motes along the ground from her feet toward it over `WayTrail` metres; `DrawHud` shows a compass at the top (see the HUD section) and changes the objective line.

**Trouble on the road.** `Journey::BuildTroubles` (after the cities are loaded) places a trouble about every `TroubleEvery` metres of road from `TroubleFirst` to `TroubleLastBefore` before the end, not within `TroubleClear` of an arena or a city, from a fixed seed, so the places are the same in every journey; the three kinds come in turn. Kinds: 0 cursed ground (a circle over one half of the road; `Hurt` with `MireDamage` while she stands in it, paced by her mercy time), 1 falling stones (within `RockfallReach` a stone is aimed near her every `RockfallEvery` seconds; `NyxaraKit::RingEffect` marks it for `RockfallWarn` seconds, then it hurts within `RockfallRadius` unless her barrier is up), 2 wisps (`WispCount` lights swinging across the road, `WispAt`; a touch within `WispTouch` hurts). `UpdateTroubles` runs with the cities' update; nothing harms her during a fight, after the journey is complete or while she is down. All harm is multiplied by `DamageTaken()`. `Draw` shows them as glow motes within 130 m; the objective line names the one within `TroubleWarn`.

**Attack timing.** All of it is constants in `GameConstants.h` (see [11-constants.md](11-constants.md)) and the input block of `NyxaraKit::Update`. A combo opens when its skill's last hit has landed (`mNextHit >= HitCount`), not at a share of the clip, so a skill keeps every hit; a mouse press from the first hit on is held in `mComboBuffer` for `ComboBufferSeconds`. `recovered()` is true once `RecoveryCancel` clip seconds have passed after the last hit of a skill or combo; from then `canStart()` lets a slash, the heavy blow, the barrier or the swap begin. `canGuard()` also lets the barrier cut a slash, the heavy blow or the swap at any time. `mBuffered` (left click) chains slash to slash and heavy to slash; `mHeavyBuffered` (right click) chains slash to heavy.

**No dodge.** `DoorwaysInputAction::Dodge` is always in `SuppressedActions` (`Game::Prepare`). The `Dodge` clip is still built into the character and is not played. Unlocked regions are not in the save file: after loading they are taken from the last arena won.

### Maps (WorldMap)

`WorldMap::View` is a plain snapshot: the road samples, how far Nyxara has walked, her position and heading, the camera yaw, living creatures, reachable closed chests, arenas, the seven city centres and which are visited, the city she is in and the next one. `Journey::FillMapView` fills it at the start of `Journey::DrawHud`. `DrawMinimap` rotates everything by the camera yaw (up = the way the camera looks) and draws the road as short `Ui::Line` segments; `DrawMap` draws the painted picture with `Ui::Image` and places markers with the extent read from `Map.txt`. The words of the cities come from `Story::Cities`.

### Cities

`Cities.txt` (written by `art/cities/build_cities.py`) lists the cities (`CITY`, with the stretch of road between their gates), their models (`M`, one texture sheet per city, loaded once), every building (`B`) and street light (`L`). `Journey::LoadCities` loads them, removes scenery props that stand where a city now is, and `Initialize` removes roaming packs inside city stretches. `UpdateCities` finds the city Nyxara is in from her distance along the road; entering shows the banner, and the first entry heals her, sets `City::Visited`, shows the gift notice and saves. Gifts are not stored as numbers: code that uses a tuning value asks `Journey::Gift(city)` (kill healing, wave and arena healing, chest healing, `DamageTaken()`, chest gold, damage scale). Visited cities are a bit mask on the fourth line of the save; an older save without it, or a test start, counts every city behind the checkpoint as visited (`MarkCitiesBehind`). Buildings have no collision: the road's leash already keeps her on the street.

## 7.5 `AmiraniMountain`

Scenery. Its collision (the walkable ledge) is part of the `RoadToAmirani` scene. Its only gameplay state is a clock for the animation and two flags set by the journey: `SetEagleAway` (the eagle has left the wound to fight) and `SetFreed` (no eagle, no chains).

| Function | What it does |
|---|---|
| `Initialize` | Builds the sky dome, moon sphere and halo quad; loads `Mountain`, `Amirani`, `Eagle`, `Dog` (`.dmesh` plus `<Name>BaseColor.png`) from `LandmarkFolder`. Finds the flat ledge in the mountain mesh and turns it toward the play area, because the importer may mirror Z. |
| `Update` | Advances the animation clock with real time, so the scene keeps moving during hit-stop. |
| `Draw` | Sky dome and moon first (centred on the camera, so they never come closer), then the mountain, Amirani (slow breathing), the eagle (wing-beat bob and a lunge at the wound every `EaglePeckPeriod`), the dog (small head motion), and four chains made of box links. |
| `StyleEnvironment` | Called from `Game::AdjustEnvironment` every frame: switches the engine's own sky panels and moon off, and sets moonlight direction and colour, ambient colour and haze. |

**Why the game draws the sky itself.** The engine lights its sky panels like scenery (ambient, directional, image-based light), which washes a painted sky out and lights each panel differently. The dome here gives every vertex the same normal, pointing along the moonlight, so the directional light adds nothing and the ambient term is equal everywhere. The moon uses the same trick and therefore always shows as a full moon.

**Capture mode.** `CAUCASIAN_EAGLE_VISTA=1` together with `CAUCASIAN_EAGLE_DEMO=1` holds the camera on the mountain and hides the combat effects and HUD.


## 7.6 `Journey`

One object, reached through `CaucasianEagle::GetJourney()`. It owns everything between the first gate of the road and the ending.

### How it shares work with the kit

The kit keeps a list of up to `MaxEnemies` (30) enemy slots: position, health, radius, push scale. In "external enemies" mode (`SetExternalEnemies(true)`) the kit stops running and drawing its own shades, but still applies Nyxara's hits, pushes, pulls and launches to whatever is in the slots. The journey fills the slots (`Spawn`), moves them (`UpdateMonsters`), notices when the kit has set a slot's health to zero (`OnDeath`) and draws them. Chests and the two chain anchors are slots too, so every attack that can hit a creature can break them.

| Kit function used by the journey | Purpose |
|---|---|
| `Enemies()`, `SetExternalEnemies` | The shared slot list |
| `SpawnOrb` | Creature projectiles; the kit moves them, blocks them with the barrier and applies their damage |
| `SetDamageScale` | Eagle Feathers and Soul Ember |
| `ResetCooldowns` | Soul Ember |
| `Effect`, `RingEffect`, `Shake`, `Notice` | Feedback |
| `SetAutoKeys` | The test pilot's attack keys |
| `GlowTexture`, `QuadMesh` | Glow cards (lanterns, barriers, telegraphs) |

### Main functions

| Function | What it does |
|---|---|
| `Initialize` | Reads `Road.txt`, loads creature and prop models, switches the kit to external enemies, reads the save (normal runs) or the test variables (unattended runs), queues the prologue cards |
| `Update` | Per frame, in this order: place on the road, death and respawn handling, `Leash`, region card, `UpdateEncounter`, `UpdateFinale`, `UpdateChests`, `UpdateMonsters`, damage scale, cards, F9 restart |
| `Leash` | Keeps the player within the road's half width, inside the arena while a fight runs, behind the gate of the next unbeaten arena, and off the ledge until the Eagle has fallen |
| `StartEncounter` / `BuildWave` / `ClearArena` | An arena fight: two or three waves bought from the region's roster with a cost budget that grows with region, arena and wave; a boss arena ends with the boss; winning heals, saves and opens the gate |
| `UpdateMonsters` | Behaviour of every creature: approach (leading her smoothed velocity, sprinting when far, swinging out to a side over the last metres, circling between blows), windup and strike, ranged volleys, leaps, keeping distance, separation from each other, staying on the road |
| `UpdateBoss` | Extra moves: Rokapi blinks and summons; the Gveleshapi sends rings of orbs and summons Ali; the Devi Lord sends rings and summons Chinka; the Eagle dives and raises wing storms |
| `UpdateChests` / `OpenChest` | Puts a chest into a slot when the player is within `ChestWakeDistance`; gives its reward when broken |
| `UpdateFinale` | Words, the Eagle fight, the two chain anchors, the ending cards |
| `Save` / `Load` | `journey.sav` ([05-data.md](05-data.md), 8.4) |
| `StyleEnvironment` | Blends fog, ambient and moonlight colour toward the current region's values |
| `Draw` | City buildings (within `CityDrawDistance`), the arena walls (stone blocks that rise while `mFighting`, driven by `mWall` 0..1 for arena `mWallArena`), props (distance-culled), chests, creatures (skinned: `BuildCreaturePalette` then `Renderer::DrawDoorwaysGpuMeshSkinned`; a creature without a `.rig` is drawn rigid), then translucent glow cards sorted back to front |
| `DrawHud` | Chapter and road progress, what she carries, the objective, the guardian bar, the region or city title, chest and city notices, the key list, the restart bar, the minimap, then the world map or the journal on top |
| `Announce`, `Notify` | Queue a title for the top of the screen; add a notice to the right edge |
| `UpdateJournal` | F1 journal and M world map: open and close, pages, scrolling, input ownership |
| `LoadCities`, `UpdateCities`, `Gift`, `MarkCitiesBehind` | The seven cities (above) |
| `FillMapView` | The snapshot the minimap and the world map draw |
| `Restart` | Begins the journey again (F9 held for `RestartHoldSeconds`) |
| `UpdatePilot` | Test pilot ([03-workflows.md](03-workflows.md), 6.11) |

### Growth: crystals, evolutions, training, potions

`Journey` owns a `Growth::State` (`mGrowth`: crystals, potions, five levels) and saves it as the last line of `journey.sav`. A save without that line (written before November 2026) is given `SaveCrystalsPerArena` crystals per arena already won.

- **Earning.** `OnDeath` adds the creature's cost (1 to 10) or `BossCrystals`; `OpenChest` adds `ChestCrystals` (3 times for a feather chest, 8 times for a king's hoard) and one to three potions. A potion beyond `MaxPotions` is drunk at once.
- **Spending.** `UpdateJournal` also runs her window: I opens it (it shares the journal's and the map's handling: input blocked, time slowed, one window at a time), W / S choose a row, Enter or Space buys `Growth::Cost` and saves.
- **Effect.** `Update` multiplies the kit's damage scale by `Growth::Damage`, sets `NyxaraKit::SetCooldownScale(Growth::Cooldown)`, the session's `FastMultiplier` (wing boost) and the player's visual scale. `DamageTaken()` includes `Growth::DamageTaken`. Maximum health stays 100: it belongs to the engine.
- **Form.** `Growth::Form` is the lowest of the three item tiers. When it rises, `Update` heals her fully, shows a banner and an effect. Nothing is stored: the form follows from the tiers.
- **Look.** `Draw` adds glow cards on her wings, at her blades, on her chest and at her feet, coloured by tier. The character model, its textures and the kit's sword colours do not change; changing shapes needs new art.
- **Potion.** `Update` reads `PotionKey` (Z). It heals `PotionHealth()` and is used up only if health was restored.
- **Balance.** Total crystals on the whole road are about 2,300 by calculation from the wave budgets; buying everything costs 2,220. `StageHealthGrowth` and `StageDamageGrowth` were raised with this feature. None of this has been played through.

### What she carries (`Collection.h`, `Collection.cpp`)

`Collection::State` is five small fields: `Charms[8]` (0..`CharmSet` per creature kind), `Links` (0..3), `Feathers` (one bit per region), `Runes[3]` (0..`MaxRunes`) and `Set` (the rune kind in her blades, or -1). Verses and keepsakes are not stored: both follow the cities she has entered (`Journey::CitiesVisited`).

| Rule | Function | Where `Journey` uses it |
|---|---|---|
| Damage to one kind of creature, when its set is complete | `DamageTo` | Each creature's `Wraith::Weak`, which the kit multiplies into damage in `DamageWraith` |
| Damage from that kind | `DamageFrom` | The creature's blow |
| Her damage (keepsakes, fire runes) | `Damage` | The kit's damage scale, with growth and city gifts |
| Damage she takes (keepsakes) | `DamageTaken` | `Journey::DamageTaken` |
| Boost (father's feathers) | `Boost` | The kit's boost scale |
| Crystals (all seven verses) | `Crystals` | Crystals a creature leaves |
| Creature attack pace (frost runes) | `CreaturePace` | Cooldown after a creature's blow |
| Health per kill (moon runes) | `KillHeal` | With the kill heal |

Where things come from: a creature that dies drops its charm with chance `CharmChance` until the set is full; a boss other than the Eagle gives a link; a gold chest of tier 1 gives a rune with chance `RuneChance`, tier 2 always; feathers lie where `PlaceFatherFeathers` puts them (a third of the way through each region, at the road's edge, not in an arena or a city) and are taken within `FatherFeatherReach`. With three links `ReachEnd(4)` unlocks the fourth passage of `EndText`.

The window: `mGrowthPage` 0 is the growth page, 1 this page (A / D switch). On page 1 W / S move `mRuneRow`, Enter sets or unsets that rune. `Collection::Draw` gets a `View` (state, cities entered, selected row, fade).

### Nature (`Nature.h`, `Nature.cpp`)

`Nature::Initialize` reads `assets/Compiled/World/Terrain.bin` (the height of the land on a 4 m grid, metres beyond the road's edge, and the region, all written by `art/world/build_nature.py`), four textures from `assets/textures/nature`, and builds six tree meshes (three broadleaf, three conifer; a trunk mesh and a leaf mesh each) and the ten rings of the cloud dome.

Nothing is stored about where things stand. A hash of the place decides, so every run is the same:

| What | Rule |
|---|---|
| Grass | 20 m squares within `GrassDistance` of the camera. A square is one mesh of tufts (three crossed cards, normals up, one of four pictures in `Grass.png`), built when first needed (at most `GrassCellsPerFrame` per frame) and dropped when unused for 240 frames once more than `GrassCellLimit` are kept. Density, height and colour come from the region table at the top of `Nature.cpp`; two layers of noise make patches |
| Trees | One candidate in each 15 m square within `TreeDistance`, 6 to 150 m beyond the road's edge; the region table gives the share of squares that hold a tree and whether it is a fir; a slow noise makes woods and clearings. Drawn as two meshes each frame, scaled per tree |
| Nothing grows | On the road, under the two lakes, on slopes steeper than `NatureMaxSlope`, at the foot of the mountain, in a city (`SetClearings`, filled by `Journey` from the cities) |
| Clouds | A dome of radius `CloudRadius` round the camera in ten rings, lower rings fainter; the picture is projected as if the cloud were a flat sheet overhead and slides with time through `TexTransform` |

`Game::Draw` draws the clouds and then grass and trees straight after the mountain and sky. Grass and leaves use alpha mask, clouds alpha blend without fog.

### Her window lists the stages

In `Growth::Draw` an item card (wings, swords, armour) lists all four stage names (`ItemName(row, 0..3)`): passed ones dim, the worn one on a band in its tier colour with WORN, the next with NEXT; under the list what she has from it now and the price and promise of the next stage. Training cards (power, defence) are unchanged. The engine inventory cannot open while the game suppresses `ToggleInventory` (engine `AppInventory.cpp`).

### How ordinary creatures fight (`Journey::UpdateMonsters`)

Per creature state added to `Monster`: `Blow` (0 light, 1 heavy, 2 second blow), `WindupFull`, `Shots`, `Slam` / `SlamWait`, `Dodge`, `Hop` / `HopDir`, `Round`.

| Behaviour | Who | Rule |
|---|---|---|
| Heavy blow | Every ordinary creature | `HeavyBlowChance` of blows: wind-up x `HeavyBlowWindup`, damage x `HeavyBlowDamage`, lands `HeavyBlowReach` beyond its reach, yellow ring, longer cooldown |
| Second blow | Wind-up under `QuickWindup` | After a light blow, `FollowUpChance`: another with wind-up x `FollowUpWindup` |
| Spring back | Radius under 0.6 m, melee | After a light blow a hop (`HopSeconds`, `HopSpeed`) away from her |
| Jump aside | Radius under 0.6 m | She is in an action (`NyxaraKit::Busy`), faces it, it is within `DodgeDistance`: once per `DodgeEvery`, `DodgeChance` to hop sideways |
| Round the guard | Ordinary creatures | Its blow was blocked: for `RoundGuardSeconds` it runs toward her back, until it is behind her |
| Hit and run | Cost 2 or less, melee, not alone | Under `WoundedShare` of health it keeps `WoundedKeep` away while its blow is not ready |
| Ground slam | Radius over 1.2 m (Uaig, Devi) | From 5 m to `SlamRange`, every `SlamEvery`: marks `SlamRadius` where she will be, strikes after `SlamSeconds` for `SlamDamage` x its blow; she is safe outside the circle, in the air, or guarding toward the giant |
| Leading shots | Every shooter, bosses too | Aimed `RangedLead` of the way to where she will be when the shot arrives |
| Fan | Creatures that keep their distance | Every `FanEvery` volleys: three shots |
| Ring of fire | Kaji | Every third shot: `KajiNovaOrbs` orbs outward |

Bosses keep their own patterns (`UpdateBoss`).

### The cage of a fight

`CageEnd(arena, end)` is where a fight is closed: `ArenaCageMargin` (20 m) beyond the arena's radius at each end. `Leash` holds her between the two ends while `mFighting`, and before the far end of an arena she has not won. It works with her exact distance along the road (the nearest sample plus her offset along its tangent) and moves her back by exactly the overshoot. Before November 2026 it snapped her to a road sample (2 m apart) each frame, which made her and the camera jump at a wall. An overshoot of more than 6 m is treated as a teleport and she is placed on the road. The walls are drawn `WallStandOff` beyond the cage end. A wall block within `WallSightNear` of the line from the camera to her sinks to 6 % of its height, rising to full height at `WallSightFar`; the band of fire on a wall is not drawn when the camera is at or behind that wall. The clearing itself is 17 m to each side (`ARENA_R` in `art/world/build_world.py`); widening it needs the world to be rebuilt in Blender.

A block also sinks when the camera itself is within `WallCameraNear` (3.2 m) of it, rising to full height at `WallCameraFar` (6.5 m); the lower of the two factors is used. Seen in a capture on 2026-11-11: with only the sight-line rule, a block beside the camera filled half the screen. The camera-distance rule has not been seen in a capture yet.

### Creature skeletons

The creature models are generated meshes without bones, and the game has no animation clips for them. They still move joint by joint:

1. **Offline, `art/monsters/rig_models.py`** reads each compiled `.dmesh`, cuts the model into 50 horizontal bands, and in each band groups the vertices into runs along x. The run on the centre line is the body, runs beside it are arms, and below the hip line the runs nearest the centre are legs. For models whose arms touch the body the table at the top of the script gives a fixed distance from the centre line instead (`arm_x`). The hip and neck heights per model are in the same table. Weights are blended over a few hundredths of the height at every joint. The script writes the four joint numbers and weights into every vertex of the `.dmesh` (the format has the fields; the static pipeline leaves them zero), sets the file's skinning flag, and writes `<Name>.rig` with the pivot of each joint. It can also write a preview picture of three poses per model.
2. **At load, `CreatureRig::Load`** reads the `.rig`. No file means the model is drawn rigid (the chest).
3. **Each frame, `BuildCreaturePalette`** computes an angle for every joint from a `CreaturePose` (walk amount, stride angle, time, windup, strike, recoil, death), then multiplies each joint's rotation about its pivot by its parent's matrix. `Journey::Draw` fills the pose from the creature's state and draws with `Renderer::DrawDoorwaysGpuMeshSkinned`.

There are 19 fixed joints, shared by number between the script and `CreatureRig.h`: pelvis, chest, head, two arms and forearms, two legs and shins (two-legged creatures); two skirt joints (Ali and Rokapi); two extra neck joints (the Gveleshapi); four wing joints (the Eagle boss). Three attacks: `Swing` (one arm), `Slam` (both arms; creatures taller than 4 m), `Cast` (hands thrust forward; creatures that keep their distance, and robed ones).

Limits: the weights come from the shape of the model, not from an artist, so skin stretches at shoulders and hips in extreme poses; hands and feet have no joints; feet slide a little because the stride is not matched to ground speed; the Eagle chained on the mountain (`AmiraniMountain`), Amirani and the dog are still rigid. Rerunning `prepare_models.py` erases the weights, so `rig_models.py` must be run after it ([03-workflows.md](03-workflows.md)).

### Sound (`Sound.h`, `Sound.cpp`)

Decides which sound file plays and when; the engine plays it (`Doorways::GameAudio()`, chapter 9).

| Function | Does |
|---|---|
| `Initialize` | Lists every `.wav` under `assets/sounds` once. A name is the folder and file name without the trailing `_number`: `combat/hit_2.wav` is a variant of `combat/hit`. Files under `voice/` keep their numbers |
| `Play(name, volume, vary)` | One-shot on the Effects volume. Picks a variant at random, not the one played last; `vary` moves the pitch by up to that fraction |
| `PlayUi(name, volume)` | One-shot on the Interface volume |
| `Update(realDt, scene)` | Every frame from `Journey::Update`. Fades music, wind, the place loop (city or fire) and the flight loop towards `scene`. Turns everything down to `NarrationDuck` while the storyteller speaks |
| `StartMusic(name)` | Starts a piece at full level at once. Used for the start screen, where the game is not updated |
| `Narrate(name)`, `StopNarration`, `Narrating` | The storyteller: one line at a time in its own slot |
| `Walk(metres)` | Footsteps: one `nyxara/step` per `StepLength` metres walked on the ground |

Engine slots used: 0 and 1 music (one fades out while the other fades in), 2 wind, 3 place, 4 storyteller, 5 flight.

Where sounds are asked for: `NyxaraKit::StartAction` (swings, skills, guard, swap, her effort), `NyxaraKit::DamageWraith` (hits, creature pain), `NyxaraKit::Hurt` (blow, her pain); `Journey` at spawn, wind-up, death, chest, walls, victory, chapter, city, memory, end, evolution, potion, death, and in `UpdateJournal` for the windows. A name with no file is silent, so a missing file is not an error.

The list of names and when each plays is `game/assets/sounds/README.md`. The files are built by `art/sounds/build_sounds.py` and `art/sounds/build_voice.py` (chapter 6).

### Death and respawn

The engine owns player death. When `CombatSystem::PlayerActionsAllowed()` turns false the journey removes the current fight; when it turns true again (the player chose respawn in the engine's screen, and the engine put her at the scene's spawn point) the journey moves her to the last arena won. If the game was not updated while she was dead, a second check catches it: she was far down the road and is suddenly in the sanctuary. Verified with the mortal test pilot ([08-testing.md](08-testing.md), 11.2a).

### Staying alive

Four rules keep a crowd from killing her at once, all in `GameConstants.h`:

- **Mercy time.** Every hit goes through `NyxaraKit::Hurt`; after a hit, further hits do nothing for `MercySeconds`.
- **Attack turns.** At most `MaxAttackers` ordinary creatures wind up a blow at the same time; the others wait. Bosses are not counted.
- **Health from the fallen.** Each creature killed gives `KillHeal` health (10; bosses excepted); every chest gives potions (see Growth); a beaten wave gives `WaveHeal`, a won arena `ArenaHeal`.
- **Slow rest.** Health returns by itself at `RegenHealth` every `RegenSeconds` (1 every 2 s) while she lives (`Journey::Update`, `mRegen`). Chests give no health: only potions to carry.
